# ugc-minimax-mode — the whole UGC/video pipeline for MiniMax

## When to use (READ FIRST)

Use this skill for EVERY UGC/video/ad job while this instance runs on **MiniMax**.
Self-test: if you cannot Read/see an image, you are on MiniMax (also recorded in
`~/.openclaw/.codex_model_state_main`). MiniMax is text-only, blind, and collapses
every format into one lone talking-head — so you DELEGATE the hard parts to Claude
and relay results to the user.

- **On MiniMax** → follow Steps 1–5 below, in order. Non-negotiable.
- **On Codex / gpt-5.5** → STOP, do not use this skill. Codex sees and composes
  natively; use `ugc-video-producer`'s normal numbered pipeline. When Codex is
  restored the instance flips back automatically.
- **Before Freedom / america250** → never use this (that is the FAL pipeline).

**Task monitor lane:** open this job's task monitor with `--lane ugc` so it routes to the UGC OPS chat (@UGCOPSbbot), separate from Before Freedom — e.g. `ID=$(~/.openclaw/scripts/task-monitor start "<short task name>" --lane ugc --stages "...")`.

All tools live in `~/.openclaw/scripts/` (global, always available). Anchor IMAGES
are generated by the user (human-in-the-loop): you hand him the prompt(s), he sends
back the image(s); you never generate the still yourself.

## Image-first shortcut (the user drops an image + says the outcome)

When the user gives you an IMAGE (e.g. a Telegram photo) and tells you the outcome he
wants ("make her say X", "have him react and laugh", "6s, she nods and points at
the camera"), you do NOT need the shot planner or a script — the image IS the
anchor. Run ONE command and it handles Grok generation, vision QA, and delivery:
```
~/.openclaw/scripts/ugc_from_image.sh --image <his_image> \
  --outcome "<what the video should do>" [--dialogue "<exact spoken line>"] \
  [--n 6] [--duration 6|10] [--voice <name|id>] --out <run>/final.mp4
```
It builds a continuity-locked Grok prompt, generates N `image_to_video` candidates
(via `ugc_grok_candidates.sh` → the reliable `grok_imagine.py` harvest), then runs
the Claude-vision QA gate (`ugc_claude_deliver.sh`) to reject drift, pick the take
that matches his image, stitch, and deliver. Returns `{out, report}`. Keep Grok
native voice unless he names a voice.

**LONGER THAN ONE CLIP (any duration > 10s — e.g. "30-second motivational video"):
Grok caps at 6/10s per clip, so use the length-aware continuity chain instead:**
```
~/.openclaw/scripts/ugc_video_from_image.sh --image <his_image> \
  --outcome "<what/vibe>" --duration 30 [--kind motivational|explainer|monologue|ad] \
  [--persona "<who>"] [--dialogue "<full script>"] [--clip-len 10|6] [--n 6] \
  [--continuity reanchor|chain] [--bible <dir>] [--voice <name|id>] --out <run>/final.mp4
```
It scripts the spoken beats (Claude), generates Grok candidates per beat, vision-QA's
each (identity lock), picks the match, and stitches into one video of the requested length.
- **`--continuity` (auto):** `reanchor` (default for talking-head/monologue/motivational)
  seeds EVERY beat from the original anchor → beats run IN PARALLEL, no compounding
  drift, fast 5-min runs; `chain` (auto for action) seeds each beat from the prior
  clip's last frame for continuous motion. Per-beat **auto-retry** (3 rounds) so a
  Grok miss doesn't kill the run; >60 clips is capped (split into segments).
- **`--bible <dir>`:** rotate close-up/medium stills from a character bible as the
  per-beat anchors → framing variety = smoother cuts. Identity is QA'd vs the bible
  master; framing/expression may vary. Build the bible first (see below).
Use this whenever the ask is longer than a single clip. For ≤10s use `ugc_from_image.sh`.

### Character bible (recurring characters — Jasmin etc.; the user supplies the master)
For a recurring character or to unlock framing variety, build a locked model sheet
ONCE from a master image the user provides (never auto-generated):
```
~/.openclaw/scripts/ugc_character_bible.sh --master <the user's image> --name jasmin
```
It derives expression/angle/framing stills from the master via identity-locked
image_edit, QA-gates each against the master, and writes `manifest.json`. Then pass
`--bible ~/.openclaw/character_bibles/jasmin` to the video tool above.

## Motion-graphics policy — ASK FIRST (do not auto-apply)

After you deliver the base stitched video, **STOP and ASK the user** whether he wants a
motion-graphics pass, offering three choices, and wait for his answer before doing it:
1. **Plain** — keep the base video as-is (no extra render).
2. **Captions + b-roll** (`--broll`) — kinetic captions, cutaway graphics, SFX.
3. **Full studio** (`--studio`) — text-behind-avatar, scroll-up headlines, in-time
   captions (note: adds ~4-5 min for the matte step).
Do NOT auto-run a motion-graphics pass — it costs real render/Grok time, so it's
the user's call. EXCEPTION: if his original request already specifies it ("studio",
"behind the avatar", "YouTube style / with graphics / b-roll", or "plain/raw"),
honor that directly and skip the question.

## Motion graphics (YouTube-creator polish — kinetic captions, brand, keyword pops)

To make a long talking-head read like a real YouTube/Shorts edit (smooth cuts,
word-by-word captions, a brand lower-third), add the Remotion motion-graphics
layer. It runs AFTER the avatar video is stitched, as a finishing pass:
```
~/.openclaw/scripts/ugc_motion_render.sh --video <stitched.mp4> --out <final_motion.mp4> \
  [--keywords "a,b,c"] [--brand-title "NAME"] [--handle "@x"] [--accent "#7CF5C4"] [--no-captions]
```
It transcribes the audio (whisper word timings), then renders kinetic captions +
brand lower-third + keyword emphasis over the footage via Remotion
(`~/.openclaw/motion-graphics`).

**STUDIO mode (`--studio`) — the premium look:** add `--studio` (optionally
`--headlines "LINE A,LINE B"`) for the high-end edit:
```
~/.openclaw/scripts/ugc_motion_render.sh --video <stitched.mp4> --out <final.mp4> \
  --studio --headlines "QUICK,QUESTION" --brand-title "STUDIO" --handle "@x"
```
- **Text BEHIND the avatar:** `ugc_matte.py` mattes the person out (U²-Net via
  onnxruntime, ProRes-4444 alpha) so headlines sit in a depth plane the avatar
  occludes — text passes behind them.
- **Scroll-up reveals:** headline words rise from nowhere with spring easing;
  staggered word entries, scale pops, parallax.
- **In-time captions:** the drift bug is fixed — captions group by natural speech
  pauses and the active word tracks the whisper timing frame-accurately.
- Note: the matte step is the slow part (~0.4s/frame on M2; ~4-5 min for 20s). Lower
  `--matte-maxside` (e.g. 540) to speed it up.

**Motion-graphic B-ROLL (`--broll`):** for a real YouTube-creator edit, add `--broll`.
Claude plans a cutaway timeline (which spoken lines cut away from the avatar's face
to a FULL-SCREEN graphic, then back), and the render interleaves them over the
continuous audio. Included automatically:
- Graphic types: kinetic typography, quote card, stat punch, AND b-roll IMAGE inserts
  (Claude writes an image prompt, Grok generates the picture, shown full-screen with
  a Ken Burns zoom + caption) for lines that name something visual.
- Transitions (punch / dissolve / slide) on every cutaway entry+exit.
- Sound effects auto-placed from a cached ElevenLabs pack: whoosh on cuts, riser into
  reveals, impact on stats, drop on the big line, swoosh on exits.
The avatar shows the rest of the time; audio/lip-sync stay continuous underneath.
```
~/.openclaw/scripts/ugc_motion_render.sh --video <stitched.mp4> --out <final.mp4> \
  --broll --brand-title "NAME" --handle "@x" --keywords "money,mindset"
``` For the length-aware tool you can do it in one
shot by adding `--motion-graphics` (plus `--keywords/--brand-title/--handle/--accent`):
```
~/.openclaw/scripts/ugc_video_from_image.sh --image <img> --outcome "<...>" --duration 30 \
  --motion-graphics --brand-title "STREET TALK" --handle "@streettalk" --keywords "money,mindset"
```
Smooth-cut reminders for long videos: cut on sentence boundaries (the scriptwriter
does this), vary framing between clips (close-up/medium from the character bible),
and let the captions carry the eye across cuts.

## The pipeline (do these in order)

### Photorealism Engine v2.0 (GLOBAL — governs every initial-frame prompt)
Every anchor/still prompt is governed by the **Photorealism Engine v2.0**. The goal is
realism, not beauty or cinematic wow: ~40% camera physics, 25% human realism, 20% lighting,
10% environment, 5% subject. The full doctrine is `~/.openclaw/PHOTOREALISM_ENGINE.md` and is
auto-synced into every SOUL.md (so you already carry it). The pipeline scripts inject the
paste-ready tails at runtime: `~/.openclaw/photorealism/ugc_anchor_directives.txt` (iPhone /
handheld → talking_head, selfie, street_interview) and `podcast_anchor_directives.txt`
(editorial → podcast). To change the standard, edit `sync_photorealism_engine.py` and re-run it;
do NOT hand-edit the SOUL blocks or directive files (they get overwritten). beforefreedom is
excluded by design.

### Step 1 — SHOT PLAN (Claude decides format/people/angles)
**Ask the continuity question up front, in the SAME batch as your other intake
questions** (before generating anything): *"Do you want these chained so it plays as
one continuous video, or are multiple clips from the same generated image (independent
cuts) fine?"* Map his answer to `--continuity continuous|multiclip|auto` (default
`auto` = let the planner decide from context). `continuous` means the planner produces
a DIFFERENT camera angle per cut (so it reads as one scene, not jump cuts back to the
same pose); `auto` reasons from the content + the feeling we want (podcast/interview →
multi-angle; intimate cooking/process → flowing continuous).

Do NOT compose the scene yourself. Run the planner; it picks the format, the
people count, the camera angles, and the continuity treatment, and writes a correct
Codex-format prompt (9:16, full Photorealism Engine v2.0 directives) for each frame:
```
~/.openclaw/scripts/ugc_shot_planner.sh --request "<what the user asked>" \
  [--product "<...>"] [--format auto|talking_head|street_interview|podcast] \
  [--continuity auto|continuous|multiclip] \
  --out <run>/shot_plan.json
```
Read `shot_plan.json` and **hand the user the `image_prompt` of EACH frame VERBATIM,
each inside its OWN fenced triple-backtick code block (tap-to-copy on Telegram) —
never as inline prose. Put the frame label OUTSIDE the block, only the prompt text
inside. Then STOP** until he sends the image(s) back:
- **talking_head / testimonial** → 1 frame, exactly ONE person, direct to camera.
- **street / public interview** → one TWO-person frame per location (interviewer
  frame-LEFT with a visible handheld mic, guest frame-RIGHT). NEVER one lone
  person, the mic is ALWAYS visible.
- **podcast** → several labelled angle frames (wide establishing, host close-up,
  guest close-up, optional over-shoulder), all the SAME people/wardrobe/set; the user
  generates each one. Hand over all the podcast prompts at once, clearly labelled.

Re-run the planner on every new scene/location/hard cut. Continuation clips in the
SAME setting do NOT need a new prompt — chain from the previous clip's last frame
(extract with ffmpeg) as the next anchor.

**Continuity standard (applies to every MiniMax UGC video going forward).** When the
plan is `continuous`/multi-angle, each cut MUST land on a genuinely different framing,
and the animator cannot invent that — so generate a SEPARATE anchor still per `framing`
in the shot plan (re-pose/re-frame the same identity via Codex/Grok `image_edit`: change
camera distance, height, and subject angle while holding face/wardrobe/set). That is what
turns a jump-cut-to-the-same-pose (the old `/private/tmp/pancake_run/` artifact) into a
natural multi-angle edit. `multiclip` plans may reuse one anchor but should still vary
framing between clips. (Port this same chaining/angle logic to `ugc-video-producer` and
`jasmine-cruz-mode` later — for now it lives here.)
Fallback (interview only, if Claude is unavailable):
`python3 ~/.openclaw/scripts/ugc_interview_prompt.py --topic "<t>" --setting mall|street`.

### Step 2 — SCRIPT (Claude writes natural dialogue)
Do NOT write the copy yourself (MiniMax writes stiff ad-speak). Offload it:
```
~/.openclaw/scripts/ugc_write_script.sh --product "<...>" --context "<audience/claim/angle/proof/lp>" \
  --format testimonial|two_person_interview|street_interview --clips <n> --out <run>/script.json
```
It returns natural, brief-schema JSON. Merge into `brief.json`. For a from-scratch ad
(no script), run `ugc-ad-strategist` for research+brief first, then this for the
writing. (Steps 1 and 2 are independent — do them in either order.)

### Step 3 — ANIMATE (Grok)
For each clip slot, generate **4–8 candidates** from the supplied anchor via Grok
`image_to_video`, named `clipN_candidate_*.mp4` (Grok drift is random; a batch
gives the QA agent a real choice). 6 or 10s, 720p.

### Step 4 — QA + DELIVER (Claude vision gate — you are blind, this is your eyes)
```
~/.openclaw/scripts/ugc_claude_deliver.sh --job <DIR> --anchor <IMG> \
  --pattern 'clips/clip*_candidate_*.mp4' --out <DIR>/final_delivery.mp4 \
  [--voice <id>] [--brief brief.json] [--criteria "..."] [--min 0.80] [--qa-only]
```
A headless Claude agent reads the anchor + extracted frames as real pixels, scores
identity/setting/composition, accepts a take ONLY if `identity_match` AND
`overall_score >= 0.80`, picks the best per slot, then voices (Step 5)/stitches
and writes the final mp4. It writes
`claude_delivery_report.json` and ends `RESULT: OK` or `RESULT: BLOCKED`.
- `--qa-only` → just pick the matching takes (no stitch/voice).
- A slot with no passing take is BLOCKED — regenerate it; do NOT lower `--min`.
- Fast no-Claude scorer (optional, in a shell loop):
  `python3 ~/.openclaw/scripts/ugc_clip_referee.py rank --anchor <a> --clips-dir clips --glob 'clip1_candidate_*.mp4' --out clips/clip1_final.mp4` (Gemini; `gate` mode exits 0 pass / 1 fail).

### Step 5 — VOICE (keep Grok native by default)
**Default: keep Grok's native audio — do NOT voice-swap unless the user asks.** On
"add a voice" / "swap the voice" / "use <name>":
```
python3 ~/.openclaw/scripts/ugc_add_voice.py --clip <clip.mp4> --voice eric --out <clip>_voiced.mp4
python3 ~/.openclaw/scripts/ugc_add_voice.py --list   # named voices
```
ElevenLabs speech-to-speech (preserves Grok timing, so lip-sync holds). Key is
already in env. Names: `brittney` (female casual), `eric` (male, default),
`charlie`, `liam`, `brian`, or a raw/cloned voice_id. Match voice to the
on-screen face.

**Using your own cloned voice:**
- Register it once with `export UGC_MY_VOICE="me=<your_elevenlabs_voice_id>"`,
  then reference it as `--voice me`. A cloned voice is a drop-in swap: only the
  voice_id in the STS step changes.
- **Use STS, never TTS, for a cloned voice.** TTS re-reads the line cold (breaks
  lip-sync) and a voice's stored defaults (high style / stability) can drift it
  to a generic accent. If yours drifts, add a `VOICE_SETTINGS` override for its
  voice_id (style 0 / stability 0.45 / similarity 1.0 / speaker_boost) in
  `ugc_add_voice.py`.

## Hard rules
- You are BLIND. NEVER accept, stitch, voice, or ship a Grok clip you have not put
  through the Claude vision gate (Step 4). It is the only thing between Grok's
  drift and the customer.
- Never let MiniMax compose the scene or write the dialogue — that is what
  Steps 1 and 2 delegate to Claude.
- Never lower `--min` below 0.80 to force a pass; fix the anchor or the Grok prompt.
- A public interview is ALWAYS two people + a visible mic; talking-head is ALWAYS
  exactly one person. The planner enforces this — trust it, do not "simplify."
- Re-prompt the user on every scene change; gate every continuation link so drift
  cannot compound.
- ALWAYS hand over any image/video prompt inside its own fenced triple-backtick
  code block (tap-to-copy on Telegram) — never as inline prose. One prompt per
  block, only the prompt text inside, label outside.
- This skill is MiniMax-only and never applies to Before Freedom / america250.
